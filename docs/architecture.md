# Карта проекта

Проект собирает дневные итоги облигаций TQCB, поддерживает историческую базу,
публикует анализ Z-спредов и показывает готовые результаты в Streamlit.

## Структура

```text

├── README.md                 Начало работы и основные команды
```

## Как идут данные

`main.py` → MOEX + Smart-Lab + ЦБ → `data/daily_data`.
При наличии истории дневной запуск догружает пропущенные опубликованные даты
в `data/history_data`. Первая полная история создаётся отдельно через `history.py`.

`analyze_spreads.py` читает дневную книгу, историю и конфигурацию →
публикует `data/spread_analysis`, включая `snapshots/YYYY-MM-DD`.
`app.py` читает завершённые публикации и согласованные дополнительные данные.

## Где менять код

| Задача | Файлы внутри `moex_bonds/` |
|---|---|
| Запросы MOEX и пагинация | `sources/moex_client.py` |
| Обогащение Smart-Lab | `sources/smartlab.py` |
| КБД и RUONIA | `sources/cbr_zcyc.py`, `sources/cbr_ruonia.py` |
| Дневной сбор и режимы запуска | `collection/main.py` |
| Фильтры, дневная таблица, XLSX | `collection/daily.py`, `collection/export_daily.mjs` |
| Исторический сбор и догрузка | `collection/history.py`, `collection/history_sync.py` |
| Защита записи и чтение истории | `storage/daily_storage.py`, `storage/history_storage.py` |
| Последовательность анализа | `analysis/analyze_spreads.py` |
| Подготовка данных, выбор корзин и весов | `analysis/spread_model.py` |
| Исторические премии и статистика | `analysis/spread_history.py` |
| Критерии аномальности и кандидаты | `analysis/spread_classification.py` |
| Прошлые расширения собственного спреда | `analysis/spread_recovery.py` |
| Итоговые таблицы и атомарная публикация | `analysis/spread_results.py` |
| Интерфейс и проверка снимков | `ui/app.py` |

Корневые скрипты делегируют исполнение пакетным модулям. Алгоритмы находятся
в пакете; изменения логики вносятся туда, без дублирования в точках запуска.
Все пути по умолчанию определены относительно расположения проекта, а не
текущей папки терминала. Дополнительная установка самого пакета не требуется.

Сборщики используют `storage`; расчёты читают сохранённые источники и пишут
отдельную публикацию. UI использует общие функции чтения и валидации,
но не запускает сбор или пересчёт. Существующие отложенные импорты между
сбором и синхронизацией сохранены; этот перенос не переписывает алгоритмы.

## Правила хранения

- Рабочие входы и результаты находятся только в `data`; временные проверочные
  запуски получают отдельный явный `--output`.
- Сырые ответы и `_support` остаются рядом с соответствующим сбором.
- Завершённые публикации содержат manifest и контрольные суммы. Сохранённые
  manifest не переписываются при переносе: старый путь дневной книги
  распознаётся только для соответствующей папки проекта; её байты проверяются.
- Драфты и старые отчёты в `archive/development` описывают историю решений,
  актуальные правила находятся в [методологии](current_methodology.md).
- Windows-окружения в `.work` остаются на исходном месте; их не переносить
  вместе с архивом. Архивные скрипты могут содержать пути прежних этапов.
- `static` остаётся рядом с корневым `app.py` для встроенной раздачи Streamlit.

Подробные команды и контракты файлов: [операционное руководство](operations.md).


## GitHub publication

`moex_bonds/publication` prepares a validated current bundle in `data/published`
and sends it through HTTPS Git. Full history and audit remain local.
Commands: `python main.py --publish` and `python main.py --publish-retry`.
See [operations](operations.md) for setup and error recovery.
